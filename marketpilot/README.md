# MarketPilot

MarketPilot is a standalone trading dashboard in this workspace. The main project remains unchanged.

## Run locally

Use Node.js 20.9 or newer:

```bash
cd marketpilot
npm install
npm run dev
```

The dashboard connects directly from the browser to Deriv's public market-data WebSocket (`wss://api.derivws.com/trading/v1/options/ws/public`). No Deriv account or API token is needed for public prices. It loads active volatility indices, historical ticks/candles, contract conditions, and live tick subscriptions. The connection retries automatically; if Deriv is unavailable, the chart shows its connection/loading state instead of substituting synthetic prices.

Charts and Demo trade settlements use Deriv market prices. No contract is submitted to Deriv or another broker. Real-wallet simulated contracts debit the user's Real wallet immediately at the displayed Deriv tick and settle at the exact duration-th subsequent live Deriv tick. Real trades use a stable pseudo-random MarketPilot digit derived from each tick's symbol, timestamp, quote, and precision; this keeps the same tick digit consistent across the browser and server. The added digit is not supplied by Deriv. The server verifies that the exact expiry tick matches Deriv history before settling the wallet. This is not actual broker execution, and Real-wallet stakes can be lost.

The market picker supports ten Deriv volatility indices (`R_10`, `R_25`, `R_50`, `R_75`, `R_100`, `1HZ10V`, `1HZ25V`, `1HZ50V`, `1HZ75V`, and `1HZ100V`) when they are available from the active-symbol response. The TradingView Lightweight Charts view can switch between an area line and candlesticks. Its 1m, 5m, 15m, 30m, and 1h controls select the history window and candle granularity. The default interval is 1m.

## Account setup

MegaPay's STK initiation response only confirms that the push was sent; it does not confirm payment. The transaction-status endpoint confirms payment with `TransactionStatus: "Completed"` and `TransactionCode: "0"`. Webhook callbacks use `ResponseCode: 0` for success and a nonzero code for a canceled or failed attempt. The app credits only verified successful transactions; nonzero callback codes and explicit failed/canceled statuses end the deposit as failed.

MarketPilot uses Supabase Auth for email/password accounts and the `marketpilot_profiles` table for account details. Copy `.env.example` to `.env.local` and set:

- `SUPABASE_URL`
- `SUPABASE_PUBLISHABLE_KEY`
- `SUPABASE_SECRET_KEY` or `SUPABASE_SERVICE_ROLE_KEY` (server only; required for payment settlement, phone-number sign-in, and Real simulated-trade settlement; never expose or commit either key)
- `MEGAPAY_API_KEY` and `MEGAPAY_ACCOUNT_EMAIL` (server only; required for M-Pesa deposits; never expose or commit these credentials)

Apply the migrations in `supabase/migrations/` to the Supabase project in timestamp order, including `20261123191000_marketpilot_tick_duration_limits.sql`, `20261123192000_marketpilot_remove_simulated_outcomes.sql`, `20261123201500_marketpilot_fixed_digit_over_under_payouts.sql`, `20261123203000_marketpilot_profile_settings.sql`, `20261123221000_marketpilot_fixed_even_odd_rise_fall_payouts.sql`, `20261123230000_marketpilot_megapay_real_wallet.sql`, `20261123233000_marketpilot_deposit_phone_and_limit.sql`, `20261123233500_marketpilot_deposit_rpc_compatibility.sql`, `20261123235800_marketpilot_withdrawal_recipient_phone.sql`, `20261124000100_marketpilot_deposit_failed_status.sql`, `20261126000100_marketpilot_payment_callback_reference_fallback.sql`, `20261126000200_marketpilot_payment_service_role_read_grants.sql`, `20261126000300_marketpilot_real_simulated_trades.sql`, `20261126000400_marketpilot_real_market_settlement.sql`, `20261126000500_marketpilot_real_market_settlement_precision.sql`, `20261126000600_marketpilot_real_trade_read_grant.sql`, `20261126000700_marketpilot_real_random_digit_settlement.sql`, `20261126000800_marketpilot_real_exact_deriv_exit.sql`, `20261126000900_marketpilot_real_pseudorandom_tick_digit.sql`, `20261126001000_marketpilot_welcome_bonus_and_payment_minimums.sql`, and `20261127230000_marketpilot_deposit_bonus_every_deposit.sql`. The payment service-role grant migration allows server-side payment verification to read transaction and wallet rows while leaving user-facing access controlled by RLS. The Real-trading migrations enable atomic stake reservation, server-verified market-tick settlement, and service-role-only balance updates. In Supabase Auth URL configuration, allow `http://localhost:3000/auth/callback` and add your production callback URL before deployment. Configure email delivery/SMTP and email confirmation in Supabase Auth to enable account confirmations and password-reset links.

Apply `20261128000100_marketpilot_admin_presence_and_withdrawals.sql` for the administrator dashboard's live activity heartbeats and completed-withdrawal totals. Active users are those whose visible session sent a heartbeat within 90 seconds; last-seen and last-login timestamps are shown separately.

Apply `20261128000200_marketpilot_admin_balance_credit.sql` to enable administrator balance credits. Each credit adds to the user's Real wallet and atomically creates a completed deposit transaction for the same USD amount; a configured KES-per-USD rate is required for the transaction record.

Signed-in users can change their full name and username from Settings and request a password reset email. Phone numbers are not editable in Settings because they are used for sign-in.

To grant administrator access, first create the account, then add its email or Auth user ID to `public.marketpilot_admins` in the Supabase SQL Editor. For example, use `insert into public.marketpilot_admins (email) values (lower('admin@example.com'));` or `insert into public.marketpilot_admins (user_id) values ('AUTH-USER-UUID');`. Admin records cannot be changed by app users. Admins are redirected to `/admin` after signing in; the server page and reporting RPC both verify the admin allowlist.

The admin report defines active accounts as having signed in within 30 days. It shows current real-wallet balances and stored trade history. Admins can configure the KES-per-USD rate and review deposits and withdrawals. Withdrawal amounts are reserved from the Real wallet when requested, must be approved before payment, and are refunded if declined. After sending M-Pesa funds manually, admins mark the withdrawal paid with its receipt/reference.

Registration requires a full name, display username, email, country, phone, password confirmation, and agreement to the Terms and Conditions. Display usernames may be shared. Email and phone sign-in use the same account; phone sign-in resolves the email server-side and does not disclose account lookup results. Password resets are delivered by email.

The profile migration creates profile rows from Supabase Auth users, enforces unique email and phone values, allows shared display usernames, and restricts profile reads with row-level security. The wallet migration creates separate USD Real and Demo wallets for every existing and newly registered user (Real starts at $0.00; Demo starts at $10,000.00). Cashier lets signed-in users view either balance; Demo can be reset to $10,000.00. Demo trades require sign-in, reserve the Demo wallet's stake at entry, and settle against incoming Deriv ticks.

Real-account simulated contracts debit the Real wallet immediately at the current live quote and settle at the exact duration-th subsequent Deriv tick. Apply `20261126000300_marketpilot_real_simulated_trades.sql`, `20261126000400_marketpilot_real_market_settlement.sql`, `20261126000600_marketpilot_real_trade_read_grant.sql`, `20261126000700_marketpilot_real_random_digit_settlement.sql`, `20261126000800_marketpilot_real_exact_deriv_exit.sql`, and `20261126000900_marketpilot_real_pseudorandom_tick_digit.sql` before enabling them. Real trades append a stable pseudo-random MarketPilot digit to each Deriv tick; the settlement route verifies and rejects any exit tick other than the exact live tick at expiry. These are MarketPilot simulations, not actual broker trades, and the added digits are not Deriv-provided.

To turn on payments, apply the payment migrations, set `MEGAPAY_API_KEY`, `MEGAPAY_ACCOUNT_EMAIL`, `SUPABASE_URL`, and either `SUPABASE_SECRET_KEY` or `SUPABASE_SERVICE_ROLE_KEY` in the server deployment environment, then sign in as an admin and set the KES-per-USD rate on `/admin`. Configure the account webhook URL as `https://your-domain/api/payments/megapay-webhook`. Successful webhook callbacks are matched against the stored deposit reference, amount, and phone before the database credits the real wallet. Every completed deposit receives an additional 50% of its deposited USD amount as a bonus. The signed-in app also polls pending deposits through the transaction-status API, five deposits per batch, rotating across the user's pending deposits. The deposit confirmation modal reconciles both provider status checks and refreshed transaction history so a webhook-completed deposit is shown as completed even if it is no longer pending when the next poll runs. Completed deposits are credited automatically without admin approval. If no final result is confirmed within two minutes, the deposit is marked Failed on the next status check when a MegaPay request ID is available; if there is no request ID, the app leaves the transaction pending for a verifiable callback rather than guessing whether payment succeeded. If the app is closed, this status check runs when it is next opened. Users can enter a recipient M-Pesa number when requesting a withdrawal. The amount is reserved immediately, and an admin must approve the request and manually send the KES amount to that recipient before marking the withdrawal paid with its receipt/reference. Do not deploy until the required migrations, Supabase redirect/email settings, credentials, and webhook URL are configured. The phone sign-in route and payment settlement use server-only Supabase credentials; these keys must never be sent to the browser.
